# Connecting an organisation

The organisation runs a NEO server edge in its approved Linux/amd64 environment. Desktop TRU Studio is not required. Its application submits selected events and retains the underlying documents and results. The edge maintains its book and follows the existing evidence path.

## Installation choices

- The organisation's administrators install the reviewed package in Kubernetes.
- A controlled LAB may run the same pinned source as isolated native processes where containers are unavailable. This is a distinct installation environment and must be tested as such.
- A hosting provider may operate separate organisation edges under agreed custody and access arrangements.

Each organisation edge has its own identity, configuration and persistent book. Do not scale replicas of the same writing identity or run a restored copy concurrently with the original.

## Partner package

The reviewed delivery should include the exact archive/checksum, installation and removal instructions, security description, application example, connection configuration and independent trust-verification instructions. Private keys are generated and retained at their intended owner location; this repository contains no credentials.

The selected LAB candidate is **2026.10.20-rc3**. Partner delivery remains held pending its release review and qualification. Earlier rc2 evidence does not qualify rc3. The current native Villanova preparation does not certify the container or an Arsys Kubernetes installation.

Use an assigned mTLS route for external connectivity. Do not expose the native intake/read ports publicly. Transport credentials do not replace membership or business mandates.

## First application event

Agree the event identity, job/order ID, actor, action, event time, result status and retained original before submitting it. Use the supplied example and the actual API contract; this document does not introduce a new event schema.

Track acceptance/booking and later FINAL separately. Fetch the proof, verify it against independently supplied trust, and repeat verification without sending the event again.
